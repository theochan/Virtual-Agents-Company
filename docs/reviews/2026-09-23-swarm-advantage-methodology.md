# Swarm comparison interpretation

The owner requested continued engineering and local Qwen comparison without further human review tasks. Model or parser checks are automated evidence, never additional human adjudication. Existing owner judgments and unknown review times retain their original provenance.

The development campaigns use repeated synthetic release logs and three correlated variants. Repeated testing after repairs is development, not independent confirmation. Every failed campaign must remain visible. A candidate win needs a separately frozen fresh-value confirmation before a final positive claim. There is no universal swarm claim, population-level statistical claim, or autonomous-planning claim from planned workflow success.

The single workflow has explicit per-source scratch checkpoints under the same root limits. Its implementation still has a fixed context envelope that can truncate source observations. A quality win may therefore demonstrate mitigation of this context-management limit, rather than an inherent model capability difference. A hand-written source parser can solve these structured fixtures without agents and is used only as a truth oracle, not claimed as an inferior competitor.

The planned workflow receives predetermined reader assignments; autonomous mode must create its own reader assignments. They must be reported separately. Costs include all workers and coordination calls. All arms use the same local model digest, source texts and required output fields. Golden answers stay outside prompts and contracts. Source identity, exact quotes, complete correct fields, current-run output and topology are checked externally.

Latency is local end-to-end elapsed time, not model-only time. The order rotates across cases but there are too few trials for a strong speed generalization. Missing usage must be reported rather than treated as free inference. No deployment, default model change, accounting qualification or general research parity follows from a positive result here.
